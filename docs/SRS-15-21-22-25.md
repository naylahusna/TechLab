# SRS-15, SRS-21, SRS-22, dan SRS-25 — Fondasi Presensi

Branch: `feature/srs-15-21-22-25-shared-state`, berbasis `fix/design-ui`.

| SRS | Implementasi                                                                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 21  | Tujuh user dummy, lima sesi (tiga status), peserta, waktu, dan dua record contoh. Skenario tanpa jadwal dan peserta kosong ikut tersedia.         |
| 22  | Satu store per provider root; identitas, sesi, dan record dalam satu snapshot. `useRole()` kompatibel, `useDemo()` menjadi API fitur.             |
| 25  | Validasi pengguna aktif, peran, penugasan, pendaftaran, urutan status, dan timestamp sebelum perubahan. Aksi tidak valid tidak mengubah snapshot. |
| 15  | Satu record per sesi/praktikan; klik berulang, pergantian pengguna, dan callback lama tidak menghasilkan duplikasi atau menimpa waktu.            |

API dan contoh integrasi tim ada di `CORE-API.md`. Tidak ada dependency tambahan,
backend, API, storage persisten, atau sinkronisasi antarperangkat. Full reload
membuat store baru. `resetDemo()` memulihkan fixture dan mengosongkan identitas.

Perubahan runtime dibatasi ke `src/core/`. Root dan seluruh screen lama tetap
menggunakan jalur impor yang sama. Folder UI praktikan/asisten tidak diubah.

## Verifikasi

- `npm test`: uji fixture, integritas data, alur demo lintas peran, validasi,
  presensi ganda, callback lama, reset, subscription, serta pembacaan sesuai peran.
- `npx expo lint` dan `npx tsc --noEmit`: pemeriksaan proyek.
- Bundle Android/iOS: memeriksa integrasi provider pada entry aplikasi.

Pengujian ini memverifikasi fondasi data/logika. Tombol, modal, feedback, dan
tampilan jadwal/rekap lengkap menjadi integrasi SRS milik owner UI.
